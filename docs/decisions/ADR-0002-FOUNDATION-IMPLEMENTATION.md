# ADR-0002 — Foundation implementation decisions

- Status: Accepted (engineering decisions within the ADR-0001 direction)
- Date: 2026-11-19
- Decision owner: Auris Nexus Technologies engineering

Each decision is reversible unless stated. Items needing client/legal confirmation are in [docs/15](../15-IMPLEMENTATION-STATUS.md).

| #   | Decision                                                                                                                        | Reason                                                                                                                                                                                | Deviation from docs                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 1   | `packages/contracts` (zod schemas + inferred types) replaces the proposed `packages/shared`.                                    | One source of truth for request/response validation and types, used by API and web.                                                                                                   | docs/04 proposed `packages/shared`; directive named `contracts`. |
| 2   | Prisma lives in `apps/api/prisma`, not `packages/database`.                                                                     | Only the API accesses the database; a separate package adds indirection with no second consumer. Extract if a second consumer (e.g. worker) appears.                                  | docs/04 proposed `packages/database`.                            |
| 3   | Roles are a Prisma enum; role→permission mapping is code (`apps/api/src/access/permissions.ts`). Permissions are not DB tables. | Versioned with the code, reviewed in PRs, unit-tested, no drift between environments. Client-editable roles are not a documented requirement. Revisit if Q04 demands it.              | docs/04 lists Role/Permission entities.                          |
| 4   | Server-side opaque sessions (hashed token in PostgreSQL, HttpOnly cookie) rather than JWTs.                                     | Immediate revocation, idle timeout, deactivation takes effect on the next request.                                                                                                    | —                                                                |
| 5   | Browser calls the API same-origin via a Next.js rewrite (`/api/*`).                                                             | First-party cookies, no cross-site cookie exposure. CORS remains configured as defence in depth. Requires the web server to reach the API; revisit if the API gets a public hostname. | —                                                                |
| 6   | CSRF protection = SameSite=Lax cookie + mandatory allow-listed `Origin`/`Referer` on state-changing requests.                   | Simple, stateless, no token plumbing. Non-browser clients must send a trusted Origin.                                                                                                 | —                                                                |
| 7   | Argon2id (`argon2` package, m=19 MiB, t=2, p=1).                                                                                | docs/05 requirement; OWASP baseline parameters. Re-tune on production hardware.                                                                                                       | —                                                                |
| 8   | Zod 4 for contracts.                                                                                                            | Patched against a published DoS advisory present in zod 3.x.                                                                                                                          | —                                                                |
| 9   | Latest-major avoidance: Prisma 6, NestJS 11, Next.js 15, Tailwind 3.                                                            | Newer majors (e.g. Prisma 7/8) change client/config models; foundation prefers proven lines. Upgrade as planned work.                                                                 | —                                                                |
| 10  | shadcn/ui _pattern_ implemented by hand (cva + tailwind-merge + Radix-free primitives).                                         | Avoids pulling the CLI/registry at this stage; components can be swapped for generated shadcn ones later. Radix primitives will be added with the first dialog/menu.                  | —                                                                |
| 11  | Audit trail is append-only via a DB trigger, plus application-role separation required in production.                           | Tamper-resistance independent of application bugs.                                                                                                                                    | —                                                                |
| 12  | No practice names/codes are seeded.                                                                                             | Q02 (practice details) is unconfirmed; inventing them would be fabricated data. Owner creates practices via `POST /api/v1/practices`.                                                 | —                                                                |
