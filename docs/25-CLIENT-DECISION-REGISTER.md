# 25 — Client Decision Register

Decisions only the client (or their advisers) can make. Engineering has **not** assumed any of them
beyond the conservative working defaults listed. "Blocks production" means real patient data must
not be loaded until it is decided. Question numbers refer to `docs/08`.

| ID                     | Decision                                                      | Why it matters                                                   | Engineering recommendation                                                             | Risk of delay                              | Blocks production |
| ---------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------ | ----------------- |
| D-ROLES (Q04)          | Final roles and permissions                                   | Current map in `access/permissions.ts` is a conservative default | Review the map with practice managers; add roles only with a matching authz-matrix row | Wrong people see or change data            | Yes               |
| D-XPRACTICE (Q05)      | Cross-practice patient/clinical visibility                    | Implemented as explicit link only                                | Keep strict; document who may create links                                             | Privacy exposure or clinical inconvenience | Yes               |
| D-MFA                  | Which roles must use MFA; exceptions                          | Production refuses to start with an empty policy                 | Require for every role with clinical, billing or admin access                          | Accounts protected by passwords alone      | Yes               |
| D-HOSTING (Q18)        | Provider, region, backup location                             | Drives encryption, residency, cost                               | South African region, managed PostgreSQL with PITR                                     | Nothing can be deployed                    | Yes               |
| D-RPO-RTO (Q19)        | Acceptable data loss and downtime                             | Sets backup design and cost                                      | Propose RPO ≤ 15 min, RTO 4 h (docs/22) for approval                                   | Over- or under-engineered backups          | Yes               |
| D-RETENTION (Q20)      | Retention periods; deletion rules                             | Nothing is deleted until defined                                 | Obtain from counsel/professional body                                                  | Unbounded data growth; POPIA exposure      | Yes               |
| D-POPIA (Q21)          | Information Officer, notices, data-subject and breach process | Governance gate (docs/23)                                        | Appoint officer first                                                                  | No lawful operating procedure              | Yes               |
| D-VAT (Q12)            | Tax/VAT treatment, invoice wording and numbering, rounding    | Tax is recorded as entered, never calculated                     | Accountant to specify; engineering will then implement and test                        | Invoices may be non-compliant              | Yes               |
| D-CLAIMS (Q11)         | Medical-aid claims in scope?                                  | Large separate module                                            | Defer after go-live                                                                    | Scope creep                                | No                |
| D-REMINDERS (Q13)      | Reminders: channels, consent, provider                        | Needs consent capture and provider contract                      | Defer; design consent model first                                                      | None for go-live                           | No                |
| D-VENDORS (Q07, Q08)   | VistaSoft / 3Shape versions, licences, vendor approval        | No integration exists; nothing assumed                           | Obtain written vendor answers (docs/20 §3)                                             | Integration estimates unreliable           | No                |
| D-IMAGING (Q09)        | Imaging formats, viewing needs, archive size                  | Drives storage, scan throughput                                  | Start with 2D viewing; DICOM/3D later                                                  | Storage cost surprises                     | No                |
| D-NOTATION (Q22)       | Dental notation, templates, terminology                       | FDI is a working default                                         | Practitioner review of chart and templates                                             | Clinical rework                            | Yes               |
| D-OFFLINE (Q17)        | Offline operation during outages                              | Not supported by design                                          | Agree a paper downtime procedure                                                       | Practice stoppage in outages               | No                |

| D-KEYS                 | Key custody and rotation owner                                | `MFA_ENCRYPTION_KEY` not rotatable today                         | Name a custodian; fund key-rotation work (S-17)                                        | Lost key forces mass re-enrolment          | Yes               |
| D-SCANNER              | Malware-scanner operation                                     | clamd must be run, updated, monitored                            | Operator owns; alert on health                                                         | Uploads blocked or unscanned               | Yes               |
| D-UAT (Q23)            | UAT participants and sign-off authority                       | Acceptance                                                       | Name them early                                                                        | Delayed go-live                            | Yes               |
| D-OWNERSHIP (Q25)      | Source-code ownership and handover terms                      | Contract                                                         | Counsel                                                                                | Dispute risk                               | No                |
